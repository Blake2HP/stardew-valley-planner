# 星露谷数值守则

这个项目是“攻略生成器”，它的价值完全取决于数字是否可信。一个凭记忆写错的生长天数，会让玩家在换季时眼看整片作物枯死。所以这里的原则是：**数字只从数据库来，计算只用公式算，跨季一定要校验**。

项目根目录下的数据库：

| 文件 | 内容 |
|---|---|
| `data/crops.json` | 作物：季节、种子价、售价、生长/再生天数、单次产量、种子来源、开售日与开售年份 |
| `data/artisan.json` | 加工规则：倍率、加成、固定价格、加工耗时 |
| `data/calendar.json` | 每季节日、采集季、换季日 |
| `data/farm.json` | 开局金币（500g，来自 wiki Gold 页面） |
| `data/bonuses.json` | 职业加成（农耕人、工匠、农业学家）与加速肥料（生长激素、高级、顶级） |
| `data/guides/*.md` | 非结构化攻略文本，只能用作思路参考，**不能作为数值来源** |

查询和计算工具都在 `scripts/sv.py`（在项目根目录运行），它直接读取上面的 JSON 文件，并把计算公式打印出来：

```bash
python .claude/skills/stardew-data-guard/scripts/sv.py crop 草莓            # 单个作物的全部字段和最晚种植日
python .claude/skills/stardew-data-guard/scripts/sv.py list --season spring --year 1  # 某季作物（给出年份时去掉当年买不到种子的）
python .claude/skills/stardew-data-guard/scripts/sv.py artisan 草莓         # 加工收益（带公式）
python .claude/skills/stardew-data-guard/scripts/sv.py profit 草莓 --plant-day 14  # 收益计算（带公式）
python .claude/skills/stardew-data-guard/scripts/sv.py profit 土豆 --professions agriculturist --fertilizer speed_gro  # 计入职业与肥料
python .claude/skills/stardew-data-guard/scripts/sv.py calendar summer      # 节日与换季信息
python .claude/skills/stardew-data-guard/scripts/sv.py simulate 玉米 --season summer --tiles 8  # 跨季收获模拟（带公式）
python .claude/skills/stardew-data-guard/scripts/sv.py check-schedule plan.json --season spring --year 1 --fix  # 跨季校验（含开售年份）
```

退出码含义：`2` 表示数据库里没有这项数据，`3` 表示校验发现了问题。

## 规则一：不许凭记忆给数值

能在对话里写出来的每一个星露谷数字，都必须有出处：要么来自 `sv.py` 或 JSON 文件，要么是用户在本次对话中明确给出的。

为什么连“我很确定”的数字也不行：游戏不同版本（1.5 / 1.6）改过不少数值；本项目的数据按 1.6 版本从 wiki 核对过，但只覆盖部分作物；而攻略生成器必须和自己的数据库保持一致，否则 Prompt 里的【数据参考】和回答里的数字会互相矛盾。

具体做法：

1. 需要某个数值时，先用 `sv.py` 查。查询结果要注明来源，例如“（来源：data/crops.json）”。
2. 如果 `sv.py` 返回退出码 2，或者问的是数据库没有覆盖的内容（**目前没有 NPC 喜好、礼物、好感度、概率掉落等数据**），就直接告诉用户“数据库中没有这项数据”，请用户提供确切数值。可以顺便提议按现有格式把它补充进 `data/`，但要等用户同意后再写入。
3. 用户提供的数值标注为“（用户提供）”。
4. `data/guides/` 里的攻略文本即使出现数字，也不能当作数值来源。如果它和 JSON 数据冲突，以 JSON 为准，并把冲突指出来。

不确定时宁可说“需要你提供 X 的确切数值”，也不要给出一个看起来合理的猜测。

## 规则二：跨季日程必须校验

只要日程涉及第 28 天、下一季第 1 天，或者包含任何种植安排，就要做跨季校验。

校验规则：

- **成熟日 = 种植日 + 生长天数，必须 ≤ 28。** 下一季仍可种植的作物（例如玉米跨夏秋）除外。
- **最晚种植日 = 28 − 生长天数。**
- **第 28 天是换季前一天，当天的目标必须包含“清理农场/停止种植”。**
- 在本季种下非本季作物，作物会立即枯萎。

操作步骤：

1. 把 28 天日程写成 JSON（`{"1": "...", ..., "28": "..."}`，也可以是带 `daily_goals` 字段的完整攻略 JSON），存到临时文件。
2. 运行 `check-schedule <文件> --season <季节> --year <年份> --fix`。给出年份时，还会检查种子在当年是否已开售（第 1 年种大蒜会报警）。脚本会把带否定的句子（“不再补种土豆”“停止种植”）和括号里的解释当作非种植内容，所以用自然的说法写日程即可，不用为了通过校验刻意改措辞。
3. 把脚本输出的每一条 ⚠️ 原样告诉用户，并采用 `--fix` 修正后的日程。对于来不及成熟的作物，建议改种或提前种植，给出的替代方案同样要用 `sv.py` 验证。
4. 每次输出跨季日程时，都要附上一个警告区块，即使校验通过也要写：

```markdown
## ⚠️ 换季校验
> ⚠️ 第 25 天：花椰菜来不及成熟，进入夏季时会枯死（成熟日 = 种植日 25 + 生长 12 天 = 37 > 28；最晚种植日 = 28 − 12 = 16）
> ⚠️ 第 28 天是换季前一天：防风草、土豆……将在进入夏季时枯死，请在此之前收获完毕。
> ℹ️ 已在第 28 天加入“清理农场/停止种植”。
```

项目代码 `stardew_planner/season_rules.py` 实现了同样的规则，`generate_strategy()` 生成攻略后会自动调用。修改这块逻辑时，要让脚本和项目代码保持一致，因为脚本本身就是调用这个模块实现的。

## 规则三：先写公式，再给结果

所有收益、倍率、天数的计算，都要按“公式 → 代入数值 → 结果”的顺序写出来，让用户能逐步核对。多步计算不要心算，直接用 `sv.py profit` 或 `sv.py artisan`，它们输出的就是这个格式。

常用公式：

| 计算项 | 公式 |
|---|---|
| 加工售价 | `基础售价 × 倍率 + 加成`（固定价产品直接取固定价；`input_crops` 专属规则优先，如小麦 → 啤酒 200g） |
| 加工溢价 | `加工售价 − 基础售价` |
| 单轮日均利润 | `(售价 × 单次产量 − 种子成本) / 生长天数` |
| 实际种植日 | `max(计划种植日, 种子最早开售日)`（草莓 = 13） |
| 能否种植（年份） | `当前年份 ≥ available_year`（大蒜、红叶卷心菜 = 2，第 1 年买不到种子） |
| 实际可用生长天数 | `28 − 种植日 + 1` |
| 收获次数（单次收获，收获后补种） | `⌊(可用天数 − 1) / 生长天数⌋` |
| 收获次数（可再生） | `1 + ⌊(可用天数 − 1 − 生长天数) / 再生天数⌋` |
| 单格整季净利 | `收获次数 × 售价 × 单次产量 − 种子数 × 种子价` |
| 最晚种植日 | `28 − 生长天数` |
| 跨季收获日 | `种植日 + 生长天数`，之后每隔再生天数一次，直到 `28 × 可连续生长季数`（夏季种玉米 = 56，即秋季末）；> 28 的日子落在下一季 |
| 季末资金（只算种植） | `期初资金 + 本季收获收入 − 种子支出 − 肥料支出`；钓鱼、挖矿等收入只能标为估算 |
| 加速后生长天数 | 查 `crops.json` 的 `speed_grow_days[总加速%]`（肥料 10 / 25 / 33 + 农业学家 10），**不要按百分比换算** |
| 农耕人售价 | `⌊基础售价 × 1.1⌋`（加工品不受影响） |
| 工匠加工品售价 | `⌊⌊基础售价 × 倍率 + 加成⌋ × 1.4⌋` |
| 肥料成本 | 每格每季一次（肥料整季留在土里）；顶级生长激素无法购买，按 0 计 |

示例：

> 草莓果酒售价 = 基础售价 × 3 = 120 × 3 = 360g（来源：data/crops.json、data/artisan.json）

职业加成和加速肥料已在 `data/bonuses.json` 中，计算时给 `sv.py` 加上 `--professions` / `--fertilizer`。**作物品质加成（银星 / 金星 / 铱星）和品质类肥料目前不在数据库里**，需要计入时先请用户提供确切数值。

## 修改本项目时

- 改动 `prompts.py` 时，要保留“数值以【数据参考】为准”和跨季约束这两条规则。
- 往 `data/*.json` 新增数据时，字段要和已有条目一致。改完后运行 `sv.py crop <新作物>` 检查能否正确读取。
- 跑完生成器（`python main.py --provider mock` 或调用真实 API）后，检查输出里是否有“⚠️ 换季校验”区块。
